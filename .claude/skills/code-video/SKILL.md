# 코드 영상 (Code Video)

HTML 파일 하나로 **손그림 셀 애니메이션처럼 보이는 장면**을 만든다. 그림은 Canvas 2D로 붓질과 잉크 선을 직접 긋고, 움직임은 시간 함수로, 소리는 Web Audio로 합성한다. 외부 이미지·음원·라이브러리 없이 오프라인에서 열린다.

핵심 생각: **AI 영상은 깎고, 코드 영상은 쌓는다.** 코드 영상의 장점은 글자 하나·색 하나·타이밍 하나를 정확히 고칠 수 있고 매번 똑같이 재현된다는 것이다. 이 장점을 살리려면 모든 그림이 "시간 t → 화면"인 순수 함수여야 한다. 그래야 아무 시점이나 스틸로 뽑아 점검하고 고칠 수 있다.

## 들어 있는 것

| 파일 | 용도 | 언제 읽나 |
|---|---|---|
| `assets/template.html` | 검증된 엔진 + 10초 데모(비 오는 밤 종이 등불). 도구·배경 레이어·셀 그리기·효과·컷 목록·필름 질감·소리·재생 제어·점검 훅이 다 있다 | **항상** 복사해서 시작 |
| `assets/example-moon-streetcar.html` | 완성 예시 80초(1990년대 OVA, 버려진 노면전차가 빛의 선로로 달까지). 13컷, 전차 미리 그리기, 실내 원근, 방향막 스크롤, 빛의 선로, 비행 패닝, 구름 셀 | 비슷한 기법이 필요할 때 해당 함수만 찾아 읽기 (파일이 크다) |

| `scripts/check_frames.js` | 스틸 프레임 추출 + 렌더 속도 측정 + 비교 시트 | 컷을 만들 때마다 |

## 작업 순서

### 1. 요청을 컷 시간표로 바꾼다

레퍼런스 프롬프트는 대개 Style / Scene / Character / Linework / Coloring / Backgrounds / Lighting / Effects / Animation / Direction / "Do not let it look like" 항목으로 나뉜다. `references/style-recipes.md` 1절 표로 항목마다 코드에서 할 일을 정한다.

그다음 **컷 시간표**를 먼저 적는다. 요청 길이(예: 80초)를 사건 순서대로 10~15컷으로 나누고, 컷마다 카메라(와이드·클로즈·익스트림 클로즈), 주인공 상태, 소리를 한 줄씩 쓴다. 감정 곡선(차갑고 조용함 → 긴장 → 따뜻한 해소)을 시간표에 표시한다. 이 표가 곧 코드의 `SHOTS`와 소리 시간표가 된다. 사용자에게 보여 줄 때도 이 표를 쓴다.

길이가 30초를 넘으면 컷 1~2개를 먼저 완성해서 스타일을 맞춘 뒤 나머지를 늘린다. 한 번에 다 쓰면 고칠 곳이 너무 많아진다.

### 2. 템플릿을 복사해 장면을 쌓는다

`assets/template.html`을 결과 파일로 복사하고 ②배경 ③캐릭터 ⑤컷 ⑦소리만 바꾼다. 엔진 부분(①도구, ④효과, ⑥필름, ⑧재생 제어)은 대개 그대로 둔다.

지켜야 할 구조와 이유:

- **모든 그림은 t의 함수로.** 파티클 배열에 상태를 쌓지 말고 `hash(i, DS)`나 "과거 시점 다시 계산(`trail`)"으로 그린다. 그래야 `renderAt(t)`로 어느 시점이든 똑같이 재현되고, 소리 시계와도 맞는다.
- **배경은 시작할 때 한 번 칠한다** (`layer` + `paint`). 매 프레임 붓질하면 24fps를 못 지킨다.
- **캐릭터는 on twos.** 상태는 `tc=Math.floor(t*12)/12`, 선 떨림은 `DS=floor(frame/2)`. 카메라만 24fps로 움직인다. 이게 "다시 그린 손그림" 느낌의 핵심이다.
- **복잡한 정적 부분은 선 떨림 3종으로 미리 그려** 번갈아 쓴다(예시의 `CARV`).
- **효과는 손으로 그은 획.** 점 파티클을 뿌리지 않는다.
- **글자·상표 금지.** 간판·번호판은 읽을 수 없는 붓 모양으로. 화면 안의 UI 문구(재생 안내)는 영상 밖 오버레이라 괜찮다.
- **특정 작품·스튜디오·캐릭터를 흉내 내지 않는다.** "시대의 일반적인 시각 언어"로 접근한다.
- **소리는 그림과 같은 시간표에서.** 소리 타이밍을 화면 함수와 같은 식으로 계산(예: 가속 공식으로 덜컹 리듬)하면 어긋나지 않는다.

### 3. 스틸로 점검하고 고친다 (가장 중요)

컷 하나를 만들 때마다 실행한다.

```bash
node <skill>/scripts/check_frames.js <결과.html> <출력폴더> "2,10.5,13.7" --sheet
```

시점을 비우면 전체에서 고르게 12장과 무작위 4장을 뽑는다. `sheet.png`를 열어 **한 장 한 장을 정지 화면으로** 본다. 레퍼런스의 기준은 "아무 프레임이나 인쇄해서 셀 원화로 걸어도 될 것"이다. 스틸로 봐야 움직임에 가려진 문제가 보인다.

점검할 것:

1. "Do not let it look like" 항목을 그대로 체크리스트로 쓴다(3D 질감, 벡터처럼 깨끗한 선, 미끄러지는 컷아웃, 파티클 느낌, 디자인이 컷마다 바뀜, 빈 배경, 반복된 사물, 탁한 색).
2. 컷마다 주인공이 화면 안에 있는지, 핵심 요소(달·광원)가 화면 끝에 걸리지 않는지.
3. 기울어지는 물체가 비정상적으로 서지 않는지.
4. 렌더 평균이 42ms(24fps) 안인지. 같은 간격으로 튀는 120ms 이상은 메모리 정리라 무시해도 되지만, 특정 컷만 느리면 고친다.
5. 오류가 없는지.

막히면 `references/style-recipes.md` 10절(실패 사례와 해결)을 먼저 본다. 실제로 겪은 문제와 해결법이 정리돼 있다.

고칠 때는 문제를 목록으로 적고 → 한꺼번에 고치고 → 같은 시점을 다시 뽑아 비교한다. 두세 바퀴면 대부분 정리된다.

### 4. 전달한다

- 결과 HTML을 사용자에게 파일로 보낸다. 브라우저로 열고 클릭하면 재생되고, Space로 일시정지, R로 처음부터 볼 수 있다는 점을 알린다.
- 컷 시간표, 레퍼런스 항목별로 무엇을 어떻게 반영했는지, 점검 결과(오류·렌더 속도)를 짧게 표로 정리한다.
- **정직하게 한계를 말한다.** 소리는 생성 오류가 없는지까지만 확인할 수 있고 직접 들을 수는 없다는 점을 밝힌다. 코드로 그린 그림이 실제 극장판 원화의 밀도에는 못 미치는 부분(가장 단순한 컷)을 짚고, 더 보강할 컷을 물어본다.
- 주소 끝에 `#t=12.5`를 붙이면 그 시점이 정지 화면으로 열린다는 것도 알려 주면 수업·발표에서 장면을 짚어 설명하기 좋다.

## 자주 쓰는 패턴 빠른 참조

- 카메라 이동: `camLerp(t, 시작, 끝, {x,y,z}, {x,y,z})` → `camSet(SX, cam.x, cam.y, cam.z)`
- 시차 배경: `drawL(SX, LAYER, f, cam.x, cam.y)` (하늘 .2 / 먼 곳 .5 / 중경 .8 / 근경 1)
- 경로 따라가기: 경로 점 + 누적 길이 표 → `onPath(거리)`가 `{x,y,ang}` 반환, 회전은 한계를 둠 (예시의 `PATH`, `onPath`)
- 하모니 프레임(감정 정점에서 정지된 회화 같은 한 장): 장면을 임시 캔버스에 그리고 필터를 한 번 걸어 붙인 뒤 0.8~1.2초 정지
- 물웅덩이 반사, 실내 1점 투시, 스크롤되는 띠(방향막), 비행 패닝, 갈라지는 구름: 예시 파일의 `reflect`, `pr`/`renderInterior`, `renderRoller`, `renderFlight`, `renderClouds`
